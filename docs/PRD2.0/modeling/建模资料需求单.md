# 建模资料需求单模板

由建模组以视觉展示够用为原则提出需求，RAG 组按单提供已有资料及缺项。不得默认把全部精确尺寸和细节图设为必需。复制下方记录到本文件或独立需求文件，并在交接台账链接；示例字段不代表已要求某个像素值或误差。

| 字段 | 填写值 |
| --- | --- |

## 建模组验收回复

资料包 ID/版本：待填。结论：待验收 / 可建模 / 需补充 / 暂不可用。缺项、冲突、是否允许先做局部以及不能验收的部分：待填。验收人、日期和证据：待填。

允许为视觉模型估算尺度或优化几何，必须单列为“视觉估算/场景调整值”，由建模组负责，不能写为官网尺寸或实测事实。引用其他对象作辅助参考需明确其用途，不能冒充目标产品资料。缺少精细资料可先做可优化初模，只把确实阻止比例/替换的缺项列为阻塞。

### 建议处理与留存规则

1. **接收并校验**：校验实际格式、可解码性及当前输入通道限制；同时记录像素尺寸。解码像素 / 内存预算需技术确认，不能仅依据文件体积判断可处理性。异常文件返回中文原因，不生成虚假的成功记录。
2. **保护原图**：原文件与派生文件分开保存，保留原始名称、来源和内容校验值；旋转、压缩、裁剪及格式转换均不覆盖原文件。存储位置、保留期限、访问范围和清理机制待 #20 确认。
3. **修正方向**：根据有效 EXIF 方向纠正派生图并一致处理方向元信息，避免二次旋转；缺少方向信息时保持原方向，人工修正作为显式操作记录。
4. **按用途生成派生图**：预览图与建模输入图区分；缩放、压缩、裁剪、背景处理仅按已确认的用途执行。不得把裁剪、抠图或 AI 生成补全后的图当作原始事实资料，派生类型和参数应可追溯。
5. **关联与版本**：在文档记录中关联 requestId、slotId、partId、bundleId 及其版本；尚未确定的值留“待填”。逐图记录原图位置、处理图位置、处理步骤、输出尺寸 / 格式、版本和状态。这里是记录要求，不是已新增的 API 字段。
6. **失败恢复**：已成功保留的原图在处理失败时仍可取用，记录失败阶段和原因；重试产生可区分的处理记录，不覆盖最后可用结果。查询状态、重试和幂等机制尚需设计，不宣称现有 Mock 已具备这些能力。
7. **交付可检查**：RAG 交原始资料、来源和缺项；本模块记录图片可读性、方向和处理结果；建模组最终判断“可建模 / 需补充 / 暂不可用”。处理成功不等于可建模，更不等于真实安装适配。

### 贴膜输入的衔接边界

贴膜参考图、生成设计图与实际应用纹理分别保存，记录派生关系和版本。参考图无需冒充已经符合 UV 的纹理；仅在取得 regionId、UV/遮罩版本、材质槽及纹理规格后，才能验证应用结果。

贴图分辨率、比例、方向、透明通道、接缝 / 留白及不可覆盖区域由模板维护方定义。本草案不指定 2K/4K 等统一值，不承担尚未分配的 UV 制作或生成服务开发任务。没有 UV 模板时可以登记参考图，但不能标记“3D 贴膜成功”。
