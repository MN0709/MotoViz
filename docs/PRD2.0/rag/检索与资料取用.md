# 检索与资料取用要求（开发暂缓，历史方案）

> 会议后决定：当前不用RAG，不继续实现本页检索/索引/API要求。已有资料可通过目录和清单取用；三位成员当前任务见[资料组入口](README.md)。下文保留原方案供以后恢复时参考，不是当前开工指令。

## 两类使用者

- 建模组：按车型、部件编号、品牌/具体型号发现产品，再以产品 ID 取完整资料包、原始参数和图片文件。
- 用户端：找到适配候选与来源；按独立 3D 资产绑定状态判断能否替换展示。

现有关键词检索与引用代码可继续评估复用；当前没有已落地的向量数据库。建模资料包的 ID 查找不必依赖向量召回。

## 规则

1. 先分清车型、年款、市场和版本；产品品牌不能代替型号或适配证据。
2. 搜索命中只表示找到候选，不能自动认定适配或建模资料完备。
3. 查询明确产品 ID 时不能随机补其他产品。无关问题或不存在的产品返回无结果与缺项信息。
4. 原始资料和检索摘要分开；图片、尺寸与文本块都带同一具体产品关联，保留来源、版本和更新时间。
5. 有来源冲突时记录待核实，不用 LLM 补造事实性尺寸、适配、价格或模型对应关系；建模组为展示采用的估算另记，不阻止近似视觉模型迭代。
6. 文本按单个产品、独立参数说明或适配记录组织，避免跨商品混块；实际切分长度通过样例验证，不照搬固定 token 数当结论。
7. 若未来引入 Embedding，先与当前检索对比：准确定位、同名不同规格、错年款排除、无结果、完整资料包获取、来源追溯及耗时。方案和指标后续由原负责人填写。
