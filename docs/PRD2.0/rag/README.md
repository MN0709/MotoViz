# RAG 组工作区

职责不变：数据组员按建模组规格补资料，检索/解析成员负责定位与引用，组长核实数据质量和交接。账号见[分工表](../shared/团队分工.md)。

## 填写入口

- [产品资料包模板](产品资料包模板.md)：复制为每个具体商品的记录，填写尺寸、图片、适配证据和缺项，并关联建模资料需求。
- [450SR 候选索引](450SR-候选索引.md)：从旧 357 条中筛出的 119 条，不是已验证商品清单。保留原行定位，不要求重采。
- [检索与资料取用](检索与资料取用.md)：说明精确 ID 查找、候选发现、引用、来源冲突和未命中行为。

## 数据分组

按“车型 → 部件编号 → 具体商品 → 资料版本”组织核实后的资料包。尚未正式定部件编号前，保留旧类别和候选号，不先造真实 partId 或适配关系。每条区分候选、证据已核实、缺建模资料、已被建模组接收等事实；资料等级与模型是否支持分别填写。

旧 [357 条原始候选 CSV](../migration/v1/rag/候选配件-357.csv) 已保留；旧三车型资料继续可追溯。2.0 首版聚焦 450SR，不删除另两款，也不擅自修改仍在 GitHub 上的三车型 10–12 条任务卡或截止时间。

优先补正在建模的具体产品所缺资料，不把收集更多无来源行数当作产出。图片应能对应同一具体产品；商品页面、适配证明和图片来源可以分开，但关系必须清楚。未查到资料就写未知。

## 资料完整度新口径

以改装可视化所需的参考资料为交付目标。建模组确认足以保持比例和可替换即可开始；精确尺寸、孔距或实物细节不足可后补，不要求所有产品达到工业复刻资料标准。资料事实与建模组视觉估算分开管理。
