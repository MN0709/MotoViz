Ethan 已授权将本版文档推送 GitHub 并通知成员。请各成员让自己正在使用的 Codex 读取本文件、PRD 正文及所属组文档，再向本人解释变化和下一步。该通知不要求重做已有成果，也不代表获准合并旧 PR 或新功能全面开工。

## 1. 如何读取

当前发布分支为 `codex/prd-2.0`，目录 `docs/PRD2.0/`。PR 未合并前，默认 main 看不到新目录；请通过文档 PR/该分支读取，或在保护本地未提交工作后以独立工作树查看，不要覆盖自己的开发分支。合并后以 main 中的目录为准。

先读 [PRD](../PRD.md)、[团队分工](团队分工.md)、[数据交接](数据关联与交接.md)，再读本组目录。旧成果只读副本及来源见 [迁移清单](../migration/迁移清单.md)。

## 2. 1.0 与 2.0 的区别

1.0 没有单一统一 PRD，这里的“1.0”指旧任务卡、接口文档和分支成果的整合基线，不表示下述能力都已实现。

| 方面 | 1.0 基线/原问题 | 2.0 当前方向 |
| --- | --- | --- |
| 核心业务 | 图片转配件3D、展示、配件检索、诊断等多模块并行 | 收敛为配件替换与贴膜拉花两个可旋转3D视觉业务 |
| 首发车型 | 已确认三车型数据基准，部分任务仍按三车型布置 | 首版只聚焦2025款450SR普通版；其他车型数据保留 |
| 建模起点 | 已有通用预设与场景草稿；真实整车拆分/商品对应尚未完整 | 建模组先列可替换部位、分组、编号与拆分边界，再制作可替换模板 |
| 质量标准 | 旧任务含真实尺度/适配验证；初稿资料要求容易被理解为精细复刻 | 比例一致、可独立替换、模型可继续优化即可；不要求与官网或实物逐处一致 |
| 生成方式 | 图片转3D服务质量/时延未达标，不能成为全部工作的前置 | 允许先生成初模再调整，保留可编辑资产；具体制作方法由原建模组提出 |
| RAG的首要交付 | 已有357条候选，产品资料与建模需求缺少对应 | 按建模组所需规格提供资料包，原始图片/参数可取用，不能只交文字摘要 |
| 数据关联 | 商品、图片、模型对应尚有缺口 | 车型模板 → 部件编号 → 具体产品/参考对象 → 资料包 → 模型及场景验证 |
| 资料精度 | 完整字段不等于可信来源，精确资料也不总能取得 | 视觉参考够用即可由建模组判断开工；事实值、未知值、视觉估算分开记录 |
| 贴膜拉花 | 业务方向已有，但缺独立完整规格 | 明确文字/参考图 → 图案 → UV/纹理 → 同一辆3D车旋转预览 |
| 无模型/近似模型 | 通用预设不得冒充真实商品，未支持则禁用挂载 | 无可用模型继续禁用；参考近似模型通过比例/替换检查可标“改装效果示意”；通用预设仍标“预设效果示意” |
| 历史成果 | 分散于main、未合并PR和数据分支 | 保留副本、版本和使用边界；迁入不代表功能验收或合并 |
| 人员分工 | 原两组、原前端协作、Ethan兼产品验收 | 完全不变；不新增第三组，不私自给新子任务改派成员 |

可视化展示不等于实物安装保证；不用精确安装证据阻塞清楚标注的近似视觉方案，但不把估算值写为实物事实。
