# 数据关联与交接规范（文档草案）

当前RAG开发暂缓，`rag/`是沿用旧路径的建模资料目录。具体三人分工见[最新分工](团队分工.md)，资料取用不要求开发检索服务。

目的：确保建模组能够调出所需资料，建模资料组明确该采什么，前端知道哪个真实商品可以替换。下列字段只用于 PRD 填报，不修改 `packages/shared` 或现有 API。

## 编号规则建议

编号稳定，不以列表顺序或品牌名作 ID；显示名称可以修改，已经引用的 ID 不随排序更换。同一商品可有不同规格和版本，需区分；同一部位可绑定多个商品，但每次场景选择需遵循占用/关联规则。

建议车型键 `cfmoto-450sr-2025-cn-standard`；它是文档建议值，当前接口没有因此获得新字段。部位可使用车型键加 `slot-001` 等序号，建模组正式定号后统一登记。本文不预先规定“排气就是 001”，避免与实际拆分冲突。

现有 `partId`、`modelId` 如已稳定，应保留或建立显式映射。357 条旧 CSV 没有现成的稳定产品 ID；本次的 `v1-row-XXXX` 仅是候选来源定位号，不是新商品 ID。对应原文件、提交和行号，不能在模型里拿它冒充正式产品编号。

## 两条关系

- 配件：vehicleId + templateVersion → slotId → partId → bundleId + version → modelId + version → 该车型内的绑定验证。
- 贴膜：vehicleId + templateVersion → regionId + UV version → designId → textureId + version → 区域预览验证。

产品可跨车型，但实际适配状态和每次场景视觉替换验证必须分别记录；不得因为某商品在 250SR 适配就自动继承到 450SR。图片、尺寸存在互相矛盾时保留原证据并标记冲突，不能覆盖成一个无出处值。

## 交接状态

状态建议：待提出需求 → 待补资料 → 待建模组验收 → 资料可建模 → 建模中 → 待场景验证 → 可展示。退回需记录缺项和下一责任方。它们是工作台账状态，不是公共 API 枚举。

**资料等级与资产状态分别管理**：候选/A 级资料 ≠ 可建模；可建模 ≠ 已有模型；已有模型 ≠ 已验证挂载。一个记录可有高质量商品证据但缺尺寸/侧面图，也可有通用 GLB 但无具体商品证据。

## 文件交接

资料包给出真实可访问原文件路径或来源链接、文件名、格式、图片分辨率/角度、已有实测/标注尺寸或比例参考及单位；未知值与建模组视觉估算分别记录。外部原图能否取用、发布或用于生成服务需记录来源许可/授权情况；网页有图片不等于已经取得再发布权。文本摘要与缩略图不能代替原图。

先在 [交接台账](交接台账.md)关联各组文件。是否新增资料下载或查询 API，由原接口负责人按 #20 对齐后决定，当前不自行扩接口。

## 视觉可用与实物准确分开

本版允许参考近似模型和可优化初模。通过场景比例、独立替换和可编辑检查即可进入标注清楚的视觉展示，不要求官网/实物一比一复刻，也不要求实际安装证据全部齐全后才制作示意模型。保留产品/参考对象关联与真实适配状态，避免视觉调整值变成RAG事实。
