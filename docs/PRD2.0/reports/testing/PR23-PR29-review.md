### P2：车型匹配分让完全无关的配件查询返回商品

文件：packages/mock-server/src/routes/rag.ts:85–96。

真实 Express、随机本地端口：POST /api/rag/search/parts，输入 {"query":"量子咖啡打印机","motorcycleModel":"川崎 Ninja 400 2021"}，返回 200、total=4，包含排气、风挡、轮胎和减震，每件 score=0.14。相同无关 query 不传车型则 total=0。正式引擎 searchParts 对同一份 Mock parts 和相同输入返回 []。

原因：车型匹配单独贡献0.14分，随后只判断score>0；没有先要求文本或部件类型相关性。前端选好车型后会把无关问题显示为有效商品结果，掩盖真实引擎的空结果路径。

要求：车型仅作为硬过滤或相关候选的排序加分，入选必须具有文本/部件类型相关性；补“有车型＋完全无关查询”以及 Mock/正式引擎同输入一致性回归。

### P2：零命中故障查询仍回填第一条故障的原因、配件和引用

文件：packages/mock-server/src/routes/rag.ts:125–140。

POST /api/rag/search/fault，输入 {"symptom":"量子咖啡打印机"}，实际200；diagnosis虽提示未精确命中，但possibleCauses仍含蓄电池电压偏低、节气门积碳，requiredParts仍含YTZ10S蓄电池和CR8E火花塞（含库存），references仍给Ninja400燃油手册。

原因：排序后无条件选择matches[0]；零分只改提示文字，其他字段照抄首条。

要求：无相关命中时明确返回资料不足，不附无关原因、配件或引用；保留合法queryId反馈登记。补零命中HTTP回归，不能仅靠更换diagnosis文字处理。

Mock的这些结果不是对真实维修事实的验证；本次不调用付费模型，不扩大到维修知识库或真实数据准确率验收。
