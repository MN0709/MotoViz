## 1. 给资料侧的首轮输入规格

以下数值是本模块提出的小样工作规格，不是模型供应商硬限制、产品已冻结指标或印刷标准。可先按此准备；不合格项说明影响后人工评估，不要求重新采集整个库。

| 项目 | 首轮要求 | 未满足时 |
| --- | --- | --- |
| 主输入 | 对应目标部位的 JPEG 或 PNG 原图；能确认目标车型/市场/年款/版本的证据单独附链接或提供方说明 | 不确定版本的图只做参考，不作为目标版本外观证据 |
| 像素 | 建议图像长边至少 1024 px，目标部位在图中最长方向至少 512 px；优先更高质量原图 | 小图保留做风格讨论；不能插值放大后声称满足原始质量 |
| 格式 / 色彩 | 原图保留，派生输入统一 JPEG/PNG、sRGB；有透明通道用 PNG | 其他格式先登记，转换后保留关联，不丢弃原图 |
| 数量 / 容量 | 每区域首轮 1 张主视角 + 1 张互补角度；油箱见下表。原图不以旧接口 4 张 / 5MB 为资料包上限 | 走旧上传接口时仍遵守其限制；本报告没有扩展接口，超限通过资料文件交接 |
| 清晰度 / 遮挡 | 主体边缘、接缝可辨，无运动模糊或强反光覆盖关键图案；主视角尽量完整显示目标区域 | 相邻件遮挡可用补图解释，不能生成猜测后当成实车证据 |
| 风格参考 | 可选 1～3 张明确允许用于此次生成的参考，或用自行编写的配色/线条文字说明 | 未核实使用范围的图保留人工讨论，不上传外部生成服务 |
| 左右关系 | 左右按骑手坐姿区分，分别记录输入；未经模型侧确认不镜像复用 | 图案文字不得直接镜像；左右 UV 不假定对称 |
| 记录 | 文件名、来源、作者/提供方、获取时间、实际像素/格式、区域、版本依据、允许用途及凭据 | 未知项写未知，不勾选资料验收通过 |

## 3. 向 #37 请求的最小模板包

五处逐一交付下列信息，先提供一处齐备包即可做验证；建议优先左主整流罩，实际由模板就绪情况决定，不缩减最终五处范围。

1. 车型模板文件与版本、正式 regionId（未定前使用中文名）、对应 mesh 名称、材质槽索引 / 名称。
2. 区域边界示意和不可贴部分；图示仅说明分区，UV 遮罩定义像素边界。
3. 与 GLB 实际一致的 UV 布局文件、UV 通道、UV 版本；是否重叠、镜像、共享其他部位。
4. 同尺寸遮罩：建议白色可贴、黑色保护，灰度边缘规则明确；这是应用合成遮罩，不直接假定与供应商编辑遮罩语义一致。
5. 基础色纹理或原材质备份；目标纹理宽高、格式、色彩空间、透明规则、朝向、接缝与留边要求。正式尺寸由模板方提供，不以输入图片 1024 px 代替纹理规范。
6. 一张带编号棋盘格应用截图及多角度证据，用于确认方向、拉伸、镜像和遮罩定位；可编辑模型源资产或后续编辑方式。

若多部位共享材质，须约定区域遮罩合成或材质隔离方式，避免给一个部位换图时其他部位一起变。不能仅凭独立 mesh 名称判断材质独立。

## 4. 首轮路线与资源

建议两阶段：先由人工监督的图像编辑工具完成授权参考图的小样，再接入已批准的 HTTP 图像编辑服务。仓库当前基线尚无本链路实现；会话可调用图像生成/编辑工具，但不代表仓库或团队已配置生产 API 账号、额度与网络。

候选：OpenAI 图像编辑 API。官方文档提供输入图编辑能力；这只能说明候选能力存在，不能证明账号可用、效果达标或能直接生成 UV。实际模型、输出规格和费用须选定后记录，当前不锁定供应商、不采购、不填虚构单张价格。[官方图像生成与编辑文档](https://developers.openai.com/api/docs/guides/image-generation)（2026-09-21 读取）。

流程：授权参考图与提示词 → 保存生成原图 → 选取图案并在分层编辑源文件中调整 → 按真实 UV 布局定位 → 用区域遮罩与原基础色合成 → 导出实际应用纹理 → 模型预览。供应商局部编辑可能偏离边界，最终非目标区域由确定性的遮罩合成保护；不能把生成结果直接当作精准 UV。

保留源图、生成图、分层编辑文件、应用纹理四类资产及版本；提示词、服务/模型版本、生成时间和修改过程随方案记录。生成图本身不保证可独立编辑其各个元素，需要保存后续分层整理成果。

成本控制建议：首轮最多 3 次生成尝试，先确认现有账号与额度；单轮费用上限由负责人批准。记录每次实际耗时和用量，包括失败重试；未知成本不承诺免费。没有已批准服务时可以做模板检查与手工纹理合成准备，不能把手工图伪报为图生图结果。

## 5. 页面交接方案（非新公共 API）

方案记录需能关联车型模板版本、中文区域 / 正式 regionId、UV 版本、方案版本、原图与生成图来源、实际纹理文件、展示标记和最后有效纹理。字段由 #20 与页面负责人对齐后才进入共享类型；本轮仅文件交接。

@Freya-Qian 页面先加载并检查新纹理，成功后替换目标材质；加载/生成失败时保持当前有效纹理，允许手动重试或恢复原车。记录哪一个方案真正应用，防止较早的异步请求覆盖较新的选择；退出时按资源所有权释放，避免销毁其他场景共用纹理。

Three.js 的纹理存在色彩空间、UV 通道及翻转等配置，接入时须按实际 GLB 验证，不能盲目复制旧图方向。颜色纹理与数据遮罩的处理应区分。[Three.js Texture 官方文档](https://threejs.org/docs/pages/Texture.html)。本报告没有实测当前渲染分支的这些配置。
