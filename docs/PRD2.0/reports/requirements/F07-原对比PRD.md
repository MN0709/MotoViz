## 1. 依据与启动条件

已明确要求来自 Issue #7、依赖任务 [Issue #5](https://github.com/MN0709/MotoViz/issues/5)及[项目说明](../../README.md)。本文核对的本地代码基线为 `438b2b6`。

Issue #7 明确规定：只有全部 P0 验收通过、剩余人力充足时，才启动本功能开发。提前撰写 PRD 不代表已满足启动条件。

本文用“建议”标注新增的产品规则，这些规则尚未获团队确认。本功能比较的是两个 3D 场景，不是上传照片的图片滑块对比。

## 2. 背景与目标

改装店工作人员向顾客展示改装方案时，需要在相同观察角度下比较车辆改装前后的外观变化，减少反复调整视角的操作。

已明确目标：提供分屏同步相机；拖动任意一侧视角时另一侧同步；对比切换响应不超过 200ms；性能不足时降级为单场景切换。

## 3. 范围与依赖

| 本期范围 | 本期不包含 |
| --- | --- |
| 改装前、改装后两个 3D 状态展示 | 照片对比、自动识别改装差异 |
| 两侧同步视角 | 多于两个方案同时比较 |
| 分屏与单场景切换 | 历史版本管理、截图 / 视频导出 |
| 加载、失败与性能降级反馈 | 车型建模、配件生成与装配算法 |

直接依赖 Issue #5 提供可工作的 3D 加载、相机交互和资源生命周期管理。还需要装配模块提供可比较的前后场景状态；这属于联调输入依赖，不代表本文为其他成员增加已确认任务。

## 4. 场景定义与输入

建议默认定义：

- 改装前：同一车型的基础场景，不含本次方案新增的配件。
- 改装后：进入对比时的当前装配方案快照。
- 两侧使用相同车型、坐标基准、相机参数、灯光和背景，避免展示条件造成误导。
- 如果用户需要比较“已有改装方案”和“新方案”，作为另一个基线定义评审，本期不默认支持。

进入对比时冻结两份状态；对比期间只调整观察视角，不编辑配件。退出后修改方案，再次进入时更新快照。以上均为建议交互规则。

建议由场景模块交付两份状态、模型资源引用、加载状态和统一相机控制能力。现有共享 `SceneState` 可作为输入基础，具体组件参数由技术评审决定；本文不预设新的后端 API。

缺少车型、必要模型或任一场景状态时不展示虚假的完整对比。前后无差异时，建议提示“当前方案没有新增改装配件”。

## 5. 主流程与页面

建议流程：查看改装方案 → 点击“前后对比” → 校验前后状态并加载资源 → 显示分屏 → 拖动或缩放同步观察 → 必要时切换为单场景 → 退出对比返回方案。

建议页面结构：顶部提供“前后对比”、显示模式及退出入口；内容区左侧标注“改装前”，右侧标注“改装后”；单场景模式提供“改装前 / 改装后”切换按钮；提供“重置视角”按钮和必要状态提示。

## 6. 功能与交互规则

| 编号 | 规则 | 状态 |
| --- | --- | --- |
| C01 | 拖动任意一侧相机时另一侧同步，不能仅支持单向同步 | 已明确 |
| C02 | 旋转、缩放、平移均同步；同步位置、观察目标及影响可见范围的投影参数 | 建议细化 |
| C03 | 相机同步应避免两个控制器互相回写形成抖动 | 建议质量要求 |
| C04 | 重置视角同时作用于两侧；使用场景模块提供的统一默认视角 | 建议 |
| C05 | 从分屏进入单场景以及切换前后状态时保留观察角度 | 建议 |
| C06 | 对比切换响应 ≤ 200ms | 已明确；测量范围见验收章节 |
| C07 | 性能不足时降级为单场景切换 | 已明确；触发阈值待确认 |
| C08 | 退出对比不修改装配方案，不丢失原页面数据；释放对比专用资源但不破坏共享资源 | 建议 |
| C09 | 调整窗口大小后仍可操作，相机比例不造成模型拉伸 | 建议 |
| C10 | 按钮有清楚标签及键盘焦点，前后状态不只靠颜色区分 | 建议 |

## 7. 性能降级方案

建议允许用户主动选择单场景模式，并在自动降级时显示“当前设备运行较慢，已切换为单场景对比”。单场景模式一次只渲染一个状态，仍能切换前后方案并保留相机视角。

自动降级建议初始方案：资源加载完成并经过 2 秒预热后，在页面可见、持续交互的条件下，平均帧率连续 3 秒低于 24 FPS，则降级；进入本次对比后不自动反复恢复分屏。此阈值是待实测和技术评审的建议值，不是现有 Issue 指标。

模型网络加载期间、后台标签页和浏览器暂停渲染期间不参与低帧率判定。WebGL 不可用或上下文丢失时，单场景也可能无法工作，应明确提示重试或返回方案，不能宣称降级成功。

移动端或窄屏是否默认单场景、断点取值，以及是否提供手动恢复分屏，需要评审确认。

## 8. 加载与异常

| 场景 | 预期行为（建议） |
| --- | --- |
| 首次进入，资源未就绪 | 展示加载反馈；禁用未就绪的前后切换 |
| 一侧必要模型加载失败 | 标明失败侧、提供重试；不得将不完整模型当成完整改装效果 |
| 缺少对比输入 | 提示先选择车型并完成方案，保留返回入口 |
| 无前后差异 | 展示说明，避免让用户误认为功能失效 |
| 性能不足 | 单次提示降级；前后切换继续可用 |
| 快速反复点击切换 | 最终显示最后选择的状态，不混入另一状态配件 |
| 退出后再次进入 | 使用最新方案快照，无重复控制器、残留画布或持续后台渲染 |
| 渲染能力不可用 | 提示无法显示 3D，允许重试或返回，不以空白页面代替反馈 |

## 9. 验收用例与性能口径

以下是待执行的验收设计，不是已完成的测试报告。新增建议项在评审确认后成为验收要求。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| AT01 | 进入同一车型的改装前后对比 | 标签正确，前后配件状态符合输入，两侧展示条件一致 |
| AT02 | 分别拖动左侧与右侧 | 双向同步，无持续抖动或递归更新 |
| AT03 | 分别在两侧缩放、平移、重置 | 两侧保持对应视角 |
| AT04 | 已加载状态下切换前后方案 | 响应 ≤ 200ms，视角保持 |
| AT05 | 在分屏与单场景之间切换 | 显示正确，无方案数据丢失 |
| AT06 | 模拟低性能条件 | 按已确认阈值降级，显示提示，单场景仍可使用 |
| AT07 | 缺输入、模型加载失败或 WebGL 不可用 | 中文反馈明确，可返回或重试 |
| AT08 | 快速连续切换 | 最终选择与实际场景一致 |
| AT09 | 连续进入退出 10 次 | 无重复交互响应、残留画布或明显资源持续增长 |
| AT10 | 调整窗口尺寸，在目标浏览器测试 | 画面比例正确，入口和按钮可用 |

建议将 200ms 定义为：模型已加载时，从用户触发前后切换到目标状态首帧呈现的时间；分屏 / 单场景模式切换单独记录。首次下载模型的时长单独报告，不混为前后切换耗时。该解释需产品验收人确认，不能自行缩小 Issue 验收范围。

建议同一验收设备执行至少 20 次前后切换，记录每次耗时及最大值，并附设备、系统、浏览器版本、模型体积 / 复杂度及显示模式。不得只用平均值代替“≤ 200ms”的验收判断。

相机同步建议以两侧相机位置、观察目标及视野参数一致性，结合连续操作录屏进行检查；数值容差和可接受的同步延迟由场景负责人确认。
