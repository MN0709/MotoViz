## 填写与维护约定

1. 建模组先提出部件编号、拆分边界和所需资料规格；RAG 组按同一编号提供具体产品资料包；建模组验收资料并制作模型，结果关联回原产品。
2. 各组在自己目录填写事实、证据、负责人、日期、状态和缺项。不要复制出多份相互独立的主清单，跨组用编号和文件链接引用。
3. `待填`、`待核实`、`示例`不得变成正式 API 输入或用户可用数据。模板中的逻辑字段不是已冻结的新接口。
4. 旧成果以副本迁入 `migration/v1/`，保留提交 SHA、原路径与校验值。归档区只读；新增核实结果写入小组文档，不覆盖旧证据。
5. 本期实际启用部件与模板预留部位分开。不要把完整拆分清单等同于首版全部建模承诺。
6. 当前提交不改变旧 Issue、公开 API、运行时代码和人员分工。历史任务与新范围冲突已登记，后续推进方式由 Ethan 另行说明。

## 最新质量口径

改装可视化优先：比例一致、可独立替换、模型可继续优化即可；不要求官网/实物一比一复刻。允许使用明确记录的视觉估算值，精确安装尺寸和完整实物细节不是统一前置条件。详见 [PRD 核心质量标准](PRD.md)。
